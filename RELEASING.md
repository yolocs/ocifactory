# Releasing ocifactory

This doc walks a maintainer through cutting an ocifactory release. The
pipeline is driven by [Goreleaser] via a manually-dispatched GitHub
Actions workflow; you supply the version, the workflow does the rest.

[Goreleaser]: https://goreleaser.com/

## What a release produces

Every successful release publishes:

- A **GitHub Release** at `https://github.com/yolocs/ocifactory/releases/tag/vX.Y.Z` with:
  - `ocifactory_X.Y.Z_<os>_<arch>.tar.gz` for `linux/amd64`, `linux/arm64`, `darwin/amd64`, `darwin/arm64`.
  - `checksums.txt` (sha256 of every archive).
  - `<archive>.sbom.cdx.json` — CycloneDX SBOM per archive (generated by [syft]).
  - `<archive>.sig` + `<archive>.cert` — cosign keyless Sigstore signatures.
- A **multi-arch container image** on GHCR: `ghcr.io/yolocs/ocifactory:vX.Y.Z` (amd64 + arm64 manifest list).
  - The image manifest is also signed with cosign keyless.
  - For non-prerelease versions, `:vX.Y` (rolling minor) and `:latest` are advanced too. Prereleases (`-rc.N`, `-beta.N`, ...) only get `:vX.Y.Z`.

[syft]: https://github.com/anchore/syft

## Prerequisites

You need:

- Write access to `yolocs/ocifactory` (so you can dispatch workflows).
- Nothing else. The workflow runs as `${{ github.actor }}`, GHCR auth uses `GITHUB_TOKEN`, and cosign signs keylessly via the workflow's OIDC token. No secrets to provision.

For local smoke tests you also need:

- [Goreleaser](https://goreleaser.com/install/) v2 in `$PATH`.
- Docker with buildx enabled (`docker buildx version` should print something).
- Optional: [syft], [cosign] — only if you want SBOMs / signatures locally.

[cosign]: https://github.com/sigstore/cosign

## Cutting a release

1. **Decide the version.** Use [semver](https://semver.org/). The workflow input is validated against `^v\d+\.\d+\.\d+(-[0-9A-Za-z.-]+)?$`. Examples:
   - `v0.1.0` — first stable release.
   - `v0.2.0-rc.1` — release candidate (will not bump `:vX.Y` / `:latest`).
   - `v1.0.0-beta.3` — beta (same prerelease treatment).
2. **Confirm `main` is green.** Releases build from whatever commit `main` points at when the workflow runs.
3. **Dispatch the release workflow.**
   - Web UI: *Actions → release → Run workflow → branch `main` → version `vX.Y.Z` → Run workflow.*
   - CLI: `gh workflow run release.yml -f version=vX.Y.Z`.
4. **Watch the run.** The workflow has three jobs:
   - `validate` — checks the version input matches the regex.
   - `tag` — creates and pushes the annotated tag `vX.Y.Z`. Fails fast if the tag already exists locally or on origin.
   - `goreleaser` — builds binaries, builds and pushes the multi-arch image, signs, generates SBOMs, and creates the GitHub Release.
5. **Smoke-test the artifacts** once the workflow goes green:

   ```sh
   docker run --rm ghcr.io/yolocs/ocifactory:vX.Y.Z --version
   # ocifactory vX.Y.Z (commit <full-sha>, linux/amd64)
   ```

## Verifying signatures

Cosign keyless signatures bind each artifact to the workflow run that produced it. The certificate identity is the workflow file in this repo, and the issuer is the GitHub OIDC provider.

Verify the container image:

```sh
cosign verify \
  --certificate-identity-regexp='https://github.com/yolocs/ocifactory/.github/workflows/release.yml@.*' \
  --certificate-oidc-issuer='https://token.actions.githubusercontent.com' \
  ghcr.io/yolocs/ocifactory:vX.Y.Z
```

Verify a release archive (download `<archive>.tar.gz`, `.sig`, `.cert` from the GitHub Release first):

```sh
cosign verify-blob \
  --certificate-identity-regexp='https://github.com/yolocs/ocifactory/.github/workflows/release.yml@.*' \
  --certificate-oidc-issuer='https://token.actions.githubusercontent.com' \
  --certificate=ocifactory_X.Y.Z_linux_amd64.tar.gz.cert \
  --signature=ocifactory_X.Y.Z_linux_amd64.tar.gz.sig \
  ocifactory_X.Y.Z_linux_amd64.tar.gz
```

## Local snapshot builds

For smoke-testing a candidate build off a feature branch without cutting a real release:

```sh
make snapshot
```

That runs `goreleaser release --snapshot --clean --skip=publish`. It produces archives under `dist/` and a loadable container image tagged `ocifactory:vX.Y.Z-next-<shortsha>` so it cannot be confused with a real release. You can then:

```sh
docker run --rm ocifactory:vX.Y.Z-next-<shortsha> --version
```

If you do not have cosign / syft installed locally, add `,sign,sbom` to the skip flag:

```sh
goreleaser release --snapshot --clean --skip=publish,sign,sbom
```

## Rolling back a bad release

If a release is broken (bad binary, missing flag, wrong base image), the cleanest fix is to **cut a new release** with the next patch version. The old release stays for traceability.

If the release must be retracted entirely (e.g. a secret leaked into an archive), remove all four pieces:

1. Delete the GitHub Release: `gh release delete vX.Y.Z --yes`.
2. Delete the git tag locally and on origin: `git tag -d vX.Y.Z && git push origin :refs/tags/vX.Y.Z`.
3. Delete the GHCR image tags: in the [GHCR package UI] delete `vX.Y.Z`, and (for non-prereleases) also `vX.Y` and `latest` if they were advanced by this release.
4. If the rolling-minor or `:latest` pointer needs to be restored to an earlier release, re-run the release workflow with that earlier version, or retag manually with `cosign copy` (preserves signatures).

[GHCR package UI]: https://github.com/yolocs/ocifactory/pkgs/container/ocifactory

## Troubleshooting

- **`tag vX.Y.Z already exists`** — Someone already cut this version. Pick the next one. Tags are immutable; do not delete and reuse.
- **`denied: installation not allowed to Create organization package`** — The repo's *Actions → General → Workflow permissions* needs `GITHUB_TOKEN` to have `write` for packages. The `release.yml` job's `permissions:` block already requests it; check the org/repo settings haven't disabled it.
- **Goreleaser fails on `docker buildx`** — The runner image must support buildx. The workflow installs QEMU + buildx via the official actions before invoking Goreleaser.
- **Cosign fails with `no token found`** — The job needs `id-token: write` for keyless signing. The `goreleaser` job has it set; if you forked the workflow, double-check it's still there.
